# 局部优化算法详解与对比 (Local Optimization Algorithms)

本文档详细解析并对比了 Edge-FML 系统中的两个核心局部优化算法：`MTDMS_CMOEA_Local.m`（标准版）和 `PAR_MTDMS_CMOEA.m`（并行/多膜增强版）。

---

## 1. MTDMS_CMOEA_Local.m (标准局部优化器)

该算法是 Edge-FML 的基础局部优化组件，实现了基于**差分进化 (Differential Evolution, DE)** 的动态约束多目标进化算法。它专为边缘设备的异构环境设计，具有自适应种群和动态约束处理能力。

### 1.1 算法流程 (Workflow)

1.  **初始化 (Initialization):**
    *   **自适应种群大小:** 根据区域的设备数量负载 (`loadFactor`) 动态计算种群大小 $N$，公式为 $N = N_{base} \times (1 + 0.5 \times Load)$。
    *   **种群生成:** 采用“可行性感知”策略初始化，通过保守的卸载概率 (30%) 和资源分配，减少初始解的不可行性。
    *   **参数初始化:** 设置动态约束阈值 $\theta_0$ 和衰减因子 $\lambda$。

2.  **进化循环 (Evolution Loop):**
    *   **步骤 1: 更新动态阈值 ($\theta_t$):**
        *   结合进化代数（时间衰减）和资源利用率（负载衰减）计算当前允许的约束违反度。
        *   公式概念：$\theta_t = \theta_0 \times (1 - \log(t)/\log(T)) \times e^{-\lambda U}$。
    *   **步骤 2: 生成子代 (Offspring Generation):**
        *   使用差分进化 (DE) 算子：$v = x_{r1} + F \cdot (x_{r2} - x_{r3})$。
        *   对离散变量（卸载决策、缓存决策）使用二进制交叉。
        *   **修复策略 (Repair):** 强制修正安全等级、资源分配总量和缓存容量约束。
    *   **步骤 3: 环境选择 (Environmental Selection):**
        *   将父代和子代合并。
        *   **可行性优先:** 将种群分为“可行解”（违反度 $\le \theta_t$）和“不可行解”。
        *   对可行解进行**非支配排序 (Non-dominated Sorting)**。
        *   如果可行解不足，从不可行解中按违反度从小到大补充。
    *   **步骤 4: 更新精英存档 (Elite Archive):** 保存历史最优的帕累托解集。

### 1.2 核心方法 (Key Methods)

*   `updateDynamicThreshold(t)`: 计算随时间收紧的约束违反阈值，初期允许探索不可行区域，后期强制收敛至可行域。
*   `generateOffspring()`: 执行 DE 变异和交叉，包含针对特定约束（如缓存容量）的贪婪修复逻辑。
*   `environmentalSelection()`: 基于 $\epsilon$-constraint 的选择机制，平衡收敛性和可行性。

### 1.3 作用 (Role)
作为大多数边缘节点的默认优化器，提供稳定、计算开销适中的多目标优化能力，适合资源受限的标准边缘设备。

## 2. PAR_MTDMS_CMOEA.m (并行/多膜增强优化器)

该算法是 `Local` 版本的高级变体，引入了**多膜 (Multi-Membrane)** 结构和**三阶段进化**策略。这里的 "PAR" 既指代 Parallel（并行膜结构），也指代其内部的 Parameter Adaptive（参数自适应）特性。

### 2.1 算法流程 (Workflow)

该算法将进化过程分为三个明确的阶段：

1.  **阶段 1: 多膜独立探索 (Multi-Membrane Exploration):**
    *   初始化 4 个独立的膜（子种群）。
    *   **差异化策略:** 每个膜采用不同的进化偏好：
        *   膜 1: `pbest` 模式（利用当前最优解引导）。
        *   膜 2: `rand` 模式（随机探索多样性）。
        *   膜 3: `latency` 偏好（倾向于降低时延的变异）。
        *   膜 4: `energy` 偏好（倾向于节能的变异）。
    *   各膜独立进化 `stage1Gen` 代。

2.  **阶段 2: 双种群协同进化 (Dual-Population Co-evolution):**
    *   将 4 个膜合并，并分裂为两个种群：
        *   **MainPop (主种群):** 执行严格的约束处理（违反度 $\approx 0$）。
        *   **AuxPop (辅助种群):** 执行宽松的约束处理（使用动态松弛变量 $\theta_{aux}$）。
    *   两个种群并行进化 `stage2Gen` 代，辅助种群帮助主种群跳出局部最优。

3.  **阶段 3: 安全性局部搜索 (Security Optimization):**
    *   从阶段 2 的结果中选出代表性解（Representatives）。
    *   针对这些精英解，专门执行**安全性优化**：
        *   固定卸载和资源决策，仅对安全等级变量 $z$ 进行精细扰动。
        *   旨在在不破坏其他目标的前提下，最大化系统的安全性（最小化风险）。

### 2.2 核心方法 (Key Methods)

*   `initializePopulation(N)`: 初始化多个膜结构。
*   `deMutation(..., mode)`: 支持多种变异模式（pbest, rand, latency, energy）的通用变异函数。
*   `environmentalSelectionStage1(...)`: 针对不同膜类型的选择策略（有的基于标量化，有的基于约束）。
*   `optimizeSecurity(...)`: 阶段 3 专用的局部搜索函数，专注于优化安全目标。

### 2.3 作用 (Role)
用于计算能力较强的边缘节点（如增强型基站），或者在需要极高质量解（High-Quality Solutions）的场景下使用。它通过增加计算复杂度和多样性探索，换取更好的帕累托前沿分布。

## 3. 算法对比 (Comparison)

| 特性 | MTDMS_CMOEA_Local (标准版) | PAR_MTDMS_CMOEA (多膜版) |
| :--- | :--- | :--- |
| **核心架构** | **单种群** (Single Population) | **多膜结构** (Multi-Membrane) -> **双种群** (Dual-Pop) |
| **进化阶段** | 单一阶段循环 | **三阶段**: 独立探索 -> 协同进化 -> 局部搜索 |
| **多样性策略** | 依赖 DE 的随机性和拥挤距离 | 依赖 4 种不同的变异策略 (Membranes 1-4) |
| **约束处理** | 单一动态阈值 $\theta_t$ | **双轨制**: 主种群严格约束 + 辅助种群宽松约束 |
| **计算复杂度** | 低 (适合资源受限设备) | 高 (需维护多个种群和多阶段计算) |
| **特化优化** | 无 | 包含专门的 **安全性 (Security)** 局部搜索阶段 |
| **适用场景** | 通用边缘计算任务，资源敏感型 | 复杂多目标问题，追求极致性能，强算力节点 |

### 总结

*   **MTDMS_CMOEA_Local** 更加**轻量级和通用**。它将复杂的约束处理集成在一个优雅的动态阈值机制中，代码结构紧凑，易于在低功耗设备上部署。
*   **PAR_MTDMS_CMOEA** 更加**复杂和强大**。它通过结构化的多阶段设计，显式地解决了多目标优化中的“收敛性 vs 多样性”以及“可行性 vs 探索性”的矛盾。特别是第三阶段的安全性搜索，使其在处理高安全需求任务时表现更佳。
